# Title bar merged into the top bar: Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The main window has no separate title strip: the app's top bar carries the window buttons and acts as the caption, with Windows' own move, snap, snap layouts and resize kept.

**Architecture:** The top bar gets three window buttons and a pure question, "what is the window area at this point?" (`TopBar::windowAreaAt`). A Windows-only `WindowFrame` subclasses the main window's HWND: it removes the caption in `WM_NCCALCSIZE` and answers `WM_NCHITTEST` from the window's resize edges and the top bar's answer, so empty bar areas are `HTCAPTION` and the buttons are `HTMINBUTTON`/`HTMAXBUTTON`/`HTCLOSE` (which is what makes Windows 11 show snap layouts). Because Windows then sends non-client mouse messages over the buttons, the frame drives the buttons' hover and press and performs their actions.

**Tech Stack:** C++20, JUCE 9.0.4, Win32 + DWM (`dwmapi.lib`), Catch2.

**Spec:** `docs/superpowers/specs/2026-11-22-title-bar-design.md`

## Global Constraints

- Build and test: `powershell -File scripts/build.ps1 -Test "<filter>"`; the whole suite is `"~[benchmark]"`; the app: `-Target SmartQLive`.
- Windows-only code behind `#if JUCE_WINDOWS`; every other platform builds and behaves as before (no buttons are shown where no frame drives them: `TopBarState::windowButtons` stays false).
- Window buttons: 46 px wide each, the bar's full height (62 px), at the far right after the EDIT/SHOW switch (the switch moves left by 3 × 46 px). Order: minimise, maximise/restore, close. Glyphs are thin 1 px lines about 10 px across in `theme::mid`; hover fills `rgba(255,255,255,.07)` (`--field`); close's hover fills `theme::danger` with a white glyph. Pressed is a little stronger than hover.
- Edit mode: an empty part of the bar is the caption. Not empty: the logo, tabs, Undo, Snapshots, pills, chips, the beat lights, the transport, the EDIT/SHOW switch, the window buttons.
- Show mode: no caption anywhere (no drag, no double-click maximise). Buttons show only when the window isn't in kiosk mode.
- Close keeps `MainWindow::closeButtonPressed`'s rule (refused while a song plays in Show mode).
- Files over about 800 lines are split. The audio thread is never touched by this work.
- Commit and push to `origin main` after each task, credited `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>` (or the model that wrote it).

## Review Focus

1. Maximised window: the top bar must not be cut off (Windows puts a maximised window's frame off-screen; `WM_NCCALCSIZE` must inset by the frame thickness when maximised).
2. Kiosk on and off (Show mode) recreates or restyles the peer: the frame must re-attach to the current HWND and never call into a destroyed window; leaving Show restores the merged bar.
3. A click on a tab, pill or the switch must never start a window drag; a drag on empty bar in Show mode must do nothing.
4. The narrowest window (1100 px) in Edit mode: tabs, pills, Undo, Snapshots, switch and buttons don't overlap.
5. DPI scaling (125 %, 150 %): hit tests convert between physical screen pixels and the component's logical coordinates.

### Task 2: The Windows frame

**Files:**
- Create: `src/ui/WindowFrame.h`, `src/ui/WindowFrame.cpp` (Windows code inside `#if JUCE_WINDOWS`; the header compiles everywhere)
- Modify: `src/ui/MainWindow.h/.cpp` (attach the frame; feed `AppShell::setWindowControls`; follow kiosk and maximised changes)
- Modify: `src/app/App.cpp` (`StartWindow`: dark native caption via `WindowFrame::paintNativeCaption`)
- Modify: `CMakeLists.txt` (link `dwmapi` on Windows) if not already linked
- Modify: `docs/acceptance.md` (a new section: the title bar, by hand), `README.md` (one line)
- Test: `tests/ui/WindowFrameTest.cpp` (Windows only, tagged `[frame]`)

**Interfaces:**
- Consumes: Task 1's `WindowArea`, `TopBar::windowAreaAt`, `setWindowButtonHighlight`, `onMinimise`/`onMaximiseToggle`/`onCloseWindow`, `AppShell::setWindowControls`.
- Produces:
  - `class WindowFrame` — `WindowFrame(juce::DocumentWindow&, std::function<WindowArea(juce::Point<int> screenLogical)> areaAt);` attaches to the window's current peer HWND (subclassing its window procedure) and follows peer changes (re-attaches; detaches before the HWND goes); destructor restores the original procedure. `bool attached() const;` `static void paintNativeCaption(juce::DocumentWindow&);` (dark mode + caption colour `theme::bg1`; no-op off Windows).
  - Pure, platform-free and tested everywhere: `int frameHitCode(WindowArea, bool maximised, bool inTopResizeBand);` returning the Win32 `HT*` value (`HTCLIENT 1, HTCAPTION 2, HTMINBUTTON 8, HTMAXBUTTON 9, HTTOP 12, HTCLOSE 20`): `inTopResizeBand && !maximised` → `HTTOP` before anything else except the buttons.
- Behaviour:
  - `WM_NCCALCSIZE` (wParam TRUE): keep the left, right and bottom frame (call the original procedure, then put back the top it moved); maximised: also inset the top by the frame thickness (`GetSystemMetricsForDpi(SM_CYFRAME) + SM_CXPADDEDBORDER`). Kiosk (full screen, no caption style): leave to the original procedure.
  - `WM_NCHITTEST`: the original procedure first; a resize edge it returns (left, right, bottom and corners) wins. Otherwise convert the physical screen point to the shell's logical coordinates (JUCE's scale factor), and return `frameHitCode(areaAt(p), IsZoomed(hwnd), p within the top 4 physical px)`.
  - Over the buttons: `WM_NCMOUSEMOVE` / `WM_NCMOUSELEAVE` (with `TrackMouseEvent` `TME_NONCLIENT | TME_LEAVE`) drive `setWindowButtonHighlight`; `WM_NCLBUTTONDOWN` on a button presses it and returns 0 (Windows must not run its own caption-button loop); `WM_NCLBUTTONUP` on the same button acts: minimise (`ShowWindow SW_MINIMIZE`), maximise toggle (`SW_MAXIMIZE` / `SW_RESTORE`), close (the window's `closeButtonPressed()`, so the Show-mode rule holds).
  - Edit-mode `HTCAPTION` gives native drag, snap and double-click maximise for free.
  - `MainWindow`: creates the frame after `setVisible(true)`; `setWindowControls(shown = !kiosk, maximised = IsZoomed)` whenever kiosk or the size changes; `onMaximiseToggle` etc. wired for platforms without a frame (JUCE `setMinimised`, `setFullScreen`-free maximise via the peer, `closeButtonPressed`). Off Windows, `setWindowControls(false, false)`.
